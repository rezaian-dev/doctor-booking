### ⚡ ۱) رزرو اتمیک نوبت — بستن شکاف TOCTOU

مشکل کلاسیک رزرو، شرایط رقابتی (race condition) است: دو کاربر هم‌زمان یک نوبت را می‌بینند، هر دو «خالی بودن» را چک می‌کنند و هر دو رزرو می‌کنند. راه‌حل ساده‌لوحانه (اول بخوان، بعد بنویس) دقیقاً همین شکاف **TOCTOU** را باز می‌گذارد.

راه‌حل این پروژه: **زمان نوبت بخشی از فیلترِ کوئری است**، پس MongoDB در یک عملیات اتمیک `findOneAndUpdate` تنها برای **یک** درخواست تطبیق می‌دهد؛ بازندهٔ رقابت `null` می‌گیرد و هیچ‌گاه دو رزرو روی یک اسلات ثبت نمی‌شود.

```ts
// 🔒 Atomically claim the slot in ONE round-trip.
// The time lives inside the query filter → MongoDB matches it for exactly
// one racing request (the loser receives null) → the TOCTOU window closes. ⚡
const claimed = await Doctor.findOneAndUpdate(
  { _id: doctorId, schedule: { $elemMatch: { date, times: time } } },
  { $pull: { "schedule.$.times": time } },
  { new: true },
);
```

> [!IMPORTANT]
> اگر ثبتِ خودِ رکورد `Appointment` شکست بخورد، اسلات نباید بی‌صدا سوخته بماند؛ یک **عملیات جبرانی (compensating action)** زمان را به برنامهٔ پزشک بازمی‌گرداند. الگوی «claim → persist → rollback-on-failure» یک ساگای مینیمالِ درست‌طراحی‌شده است. ♻️

<br/>

### ♻️ ۲) تمدید خاموش توکن روی لبه — بدون یک بایت خواندن از دیتابیس

توکن `Access` فقط ۱۵ دقیقه عمر دارد. به‌جای آنکه کاربر با انقضای آن دوباره لاگین کند، لایهٔ **Edge Proxy** (در Next.js 16 جایگزین middleware و با نامِ الزامیِ `proxy`) به‌صورت خاموش یک Access تازه صادر می‌کند.

نکتهٔ ظریف: **نقش کاربر (`role`) درون Refresh Token حمل می‌شود**، بنابراین لبه می‌تواند بدون هیچ کوئری‌ای به دیتابیس، توکن تازه بسازد و Edge-safe و سبک بماند. اعتبارسنجی قطعیِ نقش و وضعیت `ban` بعداً در لایهٔ Node (لایوت ادمین و Route Handlerها) دوباره از دیتابیس انجام می‌شود.

```ts
// 🔄 Silent refresh at the edge: access expired but refresh still valid
// → mint a fresh access token. Role rides inside the refresh token,
// so ZERO database reads happen here — the edge stays lean & Edge-safe. 🧠
if (!accessToken && refreshToken) {
  const payload = await verifyRefreshToken(refreshToken).catch(() => null);
  if (payload?.userId) {
    const role = typeof payload.role === "string" ? payload.role : "user";
    const newToken = await createAccessToken(String(payload.userId), role);
    // 🩹 forward the fresh cookie on the request too → SSR & /me read it instantly ✨
  }
}
```

> [!NOTE]
> **مدل امنیتی دولایه:** لبه یک گاردِ *خوش‌بینانه* (optimistic) است تا سریع بماند؛ منبع حقیقتِ نقش و ban، لایهٔ Node است. سرعتِ لبه بدون قربانی‌کردن قطعیت.

<br/>

### 📱 ۳) معماری SMS Relay — عبور از مسدودسازی جغرافیایی

سرویس IPPanel (پشت Cloudflare) درخواست از IP دیتاسنتر خارج از ایران را با `502` رد می‌کند — یعنی روی Vercel، ارسال پیامک عملاً غیرممکن است. راه‌حل: یک **Relay داخل ایران**.

مسیریابی هوشمند در همان provider حل شده: اگر `SMS_RELAY_URL` تنظیم شده باشد، درخواست به Relay داخل ایران forward می‌شود (تولید)؛ در غیر این صورت مستقیم IPPanel صدا زده می‌شود (توسعهٔ محلی). مهم‌تر از همه: **کلیدهای IPPanel هرگز روی Vercel قرار نمی‌گیرند** و روی Relay باقی می‌مانند.

### 🌐 ۴) Resolver ضدنشتِ localhost — SEO ضدخطای انسانی

یک باگِ رایج در تولید: نشتِ `http://localhost:3000` به تگ‌های canonical/OG و sitemap. اینجا یک **Resolver مرکزی** با ترتیب اولویت، این خطا را ساختاری غیرممکن می‌کند: حتی اگر کسی سهواً `NEXT_PUBLIC_BASE_URL=localhost` را روی Vercel بگذارد، نادیده گرفته می‌شود.

```ts
// ⭐ Explicit override wins — EXCEPT a localhost value while on Vercel.
// A stray NEXT_PUBLIC_BASE_URL=localhost must never leak into production
// canonical/OG tags. Single source of truth for every absolute URL. 🧠
const explicitIsLocal = !explicit || /localhost|127\.0\.0\.1/.test(explicit);
if (explicit && !(onVercel && explicitIsLocal)) return explicit;
```

## 🔐 امنیت

| لایه | محافظت |
|:-----|:-------|
| 🍪 **توکن‌ها** | کوکی httpOnly — مصون در برابر دسترسی جاوااسکریپت کلاینت |

| 🔢 **OTP** | کد ۵ رقمی · انقضای ۵ دقیقه · حداکثر ۳ تلاش · حداکثر ۳ ارسال در ۱۰ دقیقه |
| 👮 **RBAC** | گارد خوش‌بینانه در Edge + اعتبارسنجی قطعی نقش از DB در Node |
| ✅ **اعتبارسنجی** | Zod در تمام مرزها (API/اکشن/فرم) با regex متمرکز |

## 🔧 متغیرهای محیطی

```dotenv
# 🍃 MongoDB Atlas — رشتهٔ اتصال SRV (رمز عبور را URL-encode کنید)
MONGODB_URI="mongodb+srv://..."

# 🔐 رازهای JWT (هرکدام رشته‌ای تصادفی و طولانی)
ACCESS_TOKEN_SECRET="..."
REFRESH_TOKEN_SECRET="..."

# 📱 پیامک OTP (IPPanel)
SMS_API_KEY="..."
SMS_FROM_NUMBER="..."
SMS_PATTERN_CODE="..."

# 🇮🇷 (اختیاری · تولید) Relay برای عبور از مسدودسازی جغرافیایی IPPanel
SMS_RELAY_URL="https://your-iran-relay.example/send"
SMS_RELAY_SECRET="..."

# ⚡ Upstash Redis (OTP + rate limiting)
UPSTASH_REDIS_REST_URL="..."
UPSTASH_REDIS_REST_TOKEN="..."

# 🌐 دامنهٔ کانونیکال (برای metadataBase / OG / sitemap)
```
